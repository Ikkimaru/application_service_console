# Contributing

Use a focused branch and keep each change reviewable. Before opening a pull request:

1. Update `TASKS.md` and `CHANGELOG.md` when behavior or milestones change.
2. Add or update an ADR when a consequential architecture decision changes.
3. Never commit project-specific profiles, credentials, absolute developer paths, local settings, logs, or build artifacts.
4. Run the commands in `docs/TESTING.md` and resolve warnings rather than suppressing them without documented justification.
5. Preserve clean-architecture dependency direction and add synthetic fixtures for discovery behavior.

Commit messages should explain intent and use imperative language. Pull requests should describe the problem, solution, risks, and verification performed.
